# V5.2.4 函数链与计算复核

日期：2026-11-06。依据：`G:/逆合成结构化反馈/ficel_v524_revision_20261106/修订全文.txt`。范围：HCRA→CEMA→Builder/Gate，以及第四编§9首个有限实例、第五编§3参考编辑动作。不改原方案，不连接服务器，不运行科学实验。本次讨论来自稿件本身的运算关系，无须新增一轮广泛文献检索。

## 结论

这条链没有出现必须推倒重来的数学断点。仍值得补的主要是计算和接口边界：**有限候选不等于廉价候选；有限后验积分不等于每个任务都付得起；相同产物不等于相同动作；因预算未展开不等于已经证明无动作。**这些不是理论未定超参数的“硬错误”，也不构成已经发现现有代码有 bug。以下五项是实施前值得确定的选择或接口补全，尚未采用。

当前实际函数链应读成两条路径：

1. 开发路径：已有 Episode/反应片段 → 有限动作形成及取证 → EvidenceUnit → CEMA 条件模型 → Builder 编译有边界的 Lesson。
2. 任务路径：当前来源 → 有限形成/绑定 → 当前上下文更新 → 同一 CEMA 查询 → Gate 选择编辑或原根 → 新根完整规划 → 结果及费用回到后续版本。

CEMA 拟合和 Builder 规则开发不应因每次 Gate 查询而隐含全部重跑。相反，HCRA 的 TRANSFER_LEARNING 若启用，每个真实新增探针后确须更新它所使用的跨来源后验或代理，不能为省计算假装更新。首例不要求同时执行所有通用分支。

## 现稿已经处理，不应再次报成缺陷

- 第二编§2.1、M2：有限位置×动作、候选数及动作包大小上限；第三编§3.2：多步组合需有序、重算映射和资源，不能把效果相加。
- 第二编M1/M6、第五编§3：真实搜索状态与化学依赖分开；中间体需回根重放；映射多义保留分支或未决；产生的新根要完整重规划。
- 第一编§7、第三编§3.1/§9：候选形成、查询、诊断、特征等不能免费；消耗执行预算时要更新上下文；不能无限重估。
- 第二编§4.1.1/§4.3：相同结果不重复纳入计数，共享控制不假装独立；CEMA、Builder、Gate 不构成三份独立证据。
- 第四编§9：首例只选有限条件树和已有反应角色工具，不增建编码器，不训练第二个收益网络，不要求六组件同时训练。
- 第一编§8.2：候选遗漏、支持/拒绝和排序损失已经分开，复杂模型无法补回未进入候选域的动作。

## 1. 将“先全枚举再截断”改为按形成资源惰性展开

**具体失败场景：**实现把所有角色、砌块、产物/映射分支、祖先重放和动作组合全部生成之后，才取前K个送给 Gate。每层分支数有限、最大深度有限仍可能产生大量化学运算；候选评估还未开始，执行时间和内存已经用完。以单动作候选数A、组合深度d为例，朴素有序序列达到 O(A^d)；每步最多b个分支、重放深度h时，保留所有分支也可能达到 O(b^h)。这些是最坏情形计数，不是当前代码实测。

**现稿覆盖：**已有有限动作数、最大重放长度、每步分支上限，并且初版不必部署组合；缺的不是“再加有限”原则，而是截断发生在昂贵形成之前还是之后。

**建议运算：**现有候选提供器按预定顺序逐批返回合法分支，逐次支付反应调用、mapping、重放和属性费用；达到本次形成调用数/时间/活跃分支上限即停止展开。首例保持单个完整任务动作，多步既有回根重放不误算成自由组合。若必须保留多步编辑，只展开已经定义的少量动作包，不能先生成笛卡尔积再删减。一个全局活跃分支上限比每个节点分别给同样的分支上限更直接控制峰值资源。

**用途和代价：**防止形成阶段抢走全部资源；可能降低候选覆盖，必须保留其顺序和截断范围，不能称搜索了完整动作域。可封装旧枚举/重放工具，不要求另造化学引擎。

**停止要求：**只需一种有界提供器；若旧实现已经在化学调用前严格限制总展开，就不再改算法。未来核对实际调用与峰值内存即可，不为这一点另开大规模效果实验。

## 2. 回根构造结果要区分“无合法动作”与“还没形成完”

**具体失败场景：**一个中间体具有多个合法映射或产物，最先尝试的上游重放失败，后面的分支因形成预算被截断。若函数只返回 `NO_ACTION`，后续可能把该来源当成确实不存在可执行编辑，或将截断形成的缺口误计为化学非法率。反过来，局部产物存在但没完成根构造时，不能把局部产物直接送去当新目标。

**现稿覆盖：**已要求有限多义分支、无法消歧保持未决、局部闭合与完整根结果分开。这里是把原则落实到函数返回，不是增加新机制分类。

**建议接口：**沿用现有结果状态和 reason 字段，返回已形成的新根列表、各分支的映射/重放证据、实际费用，以及形成范围是否穷尽。至少能区分：已形成根；在已声明域确实无合法分支；映射未决；预算截断/未展开；技术错误。可以继续用已有 `availability/reason`，不必新增一套顶层状态系统。

回根构造成功只表示声明操作能产生M′，不表示该反应获实验验证；回根构造失败也只限制这个动作实例，不能推成M或其他M′无路线。新根一旦形成，按共同规划规则完整重规划，原中间体的局部成功不替代根结果。

**用途和代价：**无需增加化学求解，仅保留已有分支返回信息。旧日志若没有展开范围，保留为未知，不补写“确无动作”。若现有工具已传递这些原因，只需接口接通，无须新增算法。

## 3. 复用相同产物的计算，保留不同动作的语义

**具体失败场景：**对称角色、不同检索条目、映射路径或 Lesson 产生同一化学根结构；逐条规划会重复耗算力。若为了省算力直接合并动作记录，又会抹掉不同绑定、形成费用、继续政策和控制关系；同一个物理结果也可能被当作多个独立观察纳入后验。

**现稿覆盖：**已规定动作完整语义、共享控制、旧结果相容复用与唯一观察边界；尚未给出“化学计算共用、动作证据分别引用”的具体实现安排。

**建议运算：**按项目现有化学身份规则归并可共用计算的产物，保留“产物评估记录↔多个动作/分支”的普通引用关系。根评估只有在目标身份、规划环境、实际执行资源、scope、初态/继续政策及随机重复块均相容时才复用；不同预算的相同分子不直接视为同一结果。相关身份规则由统一接口说明，不在本建议里另造 hash 或冻结体系。

化学结果可复用不意味着效果和净值可以一并复制：某动作的形成/查找费用和失败回退仍属于其完整政策；相同结果被多个动作引用不产生新的独立来源或独立随机运行。对实际样本量按原物理运行/来源与共享块处理。

**用途和代价：**降低重复正向重放、属性计算和根规划。可优先复用旧存档；缺环境/预算/身份依据的结果不能硬复用。若重复率很低，普通字典与引用已足够，不应研发复杂缓存平台。

## 4. 明确后验与特征计算发生在哪个阶段，并设置可执行的资源传递

**具体失败场景：**每条 Lesson 的每个绑定都重新做CEMA所有条件树、κ配置与来源留出选择；每次 HCRA 探针还对每个假想结果重做完整模型选择。虽然循环有限，后验和特征的耗时仍可能比路线搜索更高。如果 Gate 评分使用剩余预算b，而评分本身持续消耗同一墙钟预算，又可能出现“评分→b变小→重新评分”的追逐。

**现稿覆盖：**已有总费用、有限积分/优化配置、实际剩余资源和禁止无限重估；原理正确。残余是首例尚未选定具体在线/离线调度，不是后验理论错误。

**建议运算：**

- CEMA条件树/模型选择与Builder规则开发在声明的开发阶段执行；部署查询读取当前版本的条件叶域后验或有限后验样本，多个相同叶域/动作查询共用统计量。实际新增证据时增量更新一次，不因读取多次重做同样推断。
- 在线更新固定模型的后验，不等于每探针都必须重新搜索全部条件树与超参数。若确实改变模型结构，明确在下一开发步骤做，不能把旧结构的后验当新结构已正确更新。
- 首例可以预先分配有限决策资源和固定执行资源，所有动作按这个已知执行资源查询；未使用决策资源是否归还由既定政策说明。这样不必边评分边无限改变比较对象。若选择共享墙钟策略，也要有有限评分轮数与超时后的原政策回退。
- 图/特征按需要读取：保留G_state与G_chem的语义关系及未展开边界，但不必在每个任务重建全历史、枚举全部路径或启动图神经编码器。旧日志引用和必要局部视图即可服务首例的角色、库存、前沿等特征；需要完整AND依赖时再读取，缺失不补成不存在。现稿已允许首例采用小特征集，这只是落实，不是取消双图研究目标。

**复杂度定位：**若有T个有限条件模型、C个参数配置、F个家族留出和一次拟合代价Fit，开发端约为 O(T·C·F·Fit)。若迁移信息计算使用A个动作、J个假想观察点、W个未来参考点，朴素每步约为 O(A·J·(Update+W·Predict))，还不含形成与路线执行；每个假想结果都再做模型选择会进一步乘上开发代价。这里不声称精确IG无需计算，只指出首例并未启用它，不应为了通用公式提前承担该成本。

**用途和代价：**避免理论完备性变成默认全量计算。复用现有版本和普通数据索引即可。未来只量测形成、特征、推断、根规划各自实际费用；未发现瓶颈时不为缓存或后验近似另开研发线。

## 5. 候选提供器要暴露覆盖限制，特别核对旧B排序是否仍适合当前目标

**具体失败场景：**当前目标以路线表现为主、任务性质可选，但候选池仍完全由旧B任务贡献分数的前K名截断。某个任务分数一般、路线明显更容易的合法候选在CEMA/Gate之前已经消失；再精细估计根效果也无法选择它。另一种情况是 Gate 全拒绝，被误判成经验无效，实则提供器没有覆盖能形成/能迁移的动作。

**现稿覆盖：**明确原B只提供候选/顺序，不自动等于路线价值；已有候选遗漏损失与首例停止节点。本建议不再追加一条新的理论上界。

**建议接口：**候选提供器同时给出使用的有限池、生成/排序依据、已形成数量、合法数量、预算截断数量或可报告范围，以及是否存在未展开项。Gate另外给支持拒绝和收益拒绝；不要合成一个“失败率”。若旧排序仍服务任务性质，应在方案中明确这只是当前候选入口，并核对是否保留少量按角色合法性、结构差异或预定顺序取得的候选，避免所有机会都由旧目标决定。

这不是立即扩大K或开发一个新检索模型。先检查旧池和排序字段，区分“提供器没有可用机会”与“有机会但条件经验选错”。只有确有前者且有可复用更宽候选池时，才讨论一次有限覆盖对照；没有这种证据，不持续扩大池或细分来源。

**用途和代价：**让首例阴性有可诊断含义，避免又进入不断改CEMA/课程的循环。旧候选和已有根结果可先用于开发核对；未测候选保持未测，不假造其可解性。当前没有核验实际候选排行，因此这里只提出条件风险，不断言旧B实现已造成错配。

## 是否真的需要全部图与机制抽象

首个有限实例需要可执行动作、动作前特征、来源/控制关系、同一CEMA效应、合法绑定和完整根评价。它不需要同时训练故障多标签、全局双图编码器、相容关系网络、复杂神经条件模型及六类接收端，也不需要先给所有失败找到唯一机制。V5.2.4已经明确这些是可替代分支，不应再把“全部实现”作为走通首例的前提。

然而，若论文最终要主张“双图诊断或跨来源机制抽象提供增量”，就需要这些信息实际改变候选、条件或选择，并与同候选域的简化方法比较。只实施有限角色条件树是合法的首例，不能自动替全部HCRA/机制抽象背书。先走通这条短链，是检查方法究竟在哪一步产生新增价值；不是承诺删掉原来的研究目标。

## 建议处理顺序

实施前优先确定第1、2、4项，使调用有明确输出和实际可支付边界；第3项在有重复时直接用普通结果引用复用；第5项核对已有候选目录和排序，不凭想象启动新实验。本次只写审查笔记，以上建议均未写入原方案。
